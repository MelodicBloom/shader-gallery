## Repository-specific records

### D18 — Shader Gallery: research laboratory, material atlas, and visible proof

**Use when:** When extending shader-gallery, material validation, optical studies, previews, art direction, or portfolio presentation.

[Recovered intent] The current README joins interactive GLSL material studies, a manifest-driven library, reproducible previews, native compile/link/render validation, browser QA, and source attribution. It names thin-film, opal-like domains, oriented labradorite-like plates, dispersion, nacre, and controlled lighting.

[Design DNA] Preserve brilliant inner fire, coherent view/light response, material-specific structure, and readable comparison controls. Show the material prominently, followed by its mechanism, parameters, reference, provenance, limitations, and observed behavior. The research atlas should also be a clear visual portfolio artifact.

[Observed state] The fetched main tree includes material shaders and preview assets. The README records a live-demo link and identifies Material Validation Lab directions: Khronos abalone, bubble thin-film versus an RGB-proxy control, and original procedural gold foil. This pass did not run those studies, inspect current PR checks, or verify the live site on mobile.

[Repair resolution — proposed] Keep study, baseline/reference, authored approximation, preview integrity, physical calibration, and device performance as separate evidence dimensions. A source/asset hash proves integrity, not visual correctness. Restore the full material atlas roadmap while retaining controlled view/light/grazing comparisons for each mechanism.

[Reimagined horizon] An optical field guide with interactive specimens, comparison fixtures, explanatory diagrams, reusable recipes, citations/credit, downloadable evidence, and links to adoption paths in AETHER/Wildfire. Do not prematurely select a universal rendering framework.

[Carry-forward test] One visitor can see the hero evidence, open the live study, change meaningful controls, understand what was actually tested, and use a keyboard/static fallback. For measured claims, require provenance-bearing constants and comparison data.

## Practical continuation contract

1. Re-read current repository instructions and source before implementation. The baseline above identifies this publication, not a permanent execution HEAD.
2. Retain the full design horizon separately from the current demonstrator. Name what the demonstrator preserves, approximates, defers, or cannot prove.
3. Map tokens and controls to actual consumers with explicit units, ownership, accessible alternatives, and observable effect.
4. Complete the relevant interaction/error/cancellation states before promoting a reusable component.
5. Pair source/runtime checks with human correspondence review against the actual visual inspiration.
6. Keep proposed repairs unexecuted until a later implementation records its own revision, checks, and evidence.
